# Архитектура сервера — ROMALEX

[[ROMALEX]] | [[Таблица учёта по проектам]]

## Концепция

Домашний сервер Арсения стоит дома, папина фирма использует его как IT-инфраструктуру. Арсений обслуживает и развивает. Для фирмы это дешевле VPS в долгосроке, данные не уходят в чужое облако.

**Домены фирмы:** `romalex.ru` и `romalex.su`

---

## Распределение доменов

| Домен | Назначение | Доступ |
|---|---|---|
| `romalex.ru` | Лендинг фирмы | Публичный |
| `db.romalex.ru` | Таблица складского учёта | Только сотрудники |
| `files.romalex.ru` | Nextcloud — файловое хранилище | Только сотрудники |
| `api.romalex.ru` | FastAPI бэкенд | Внутренний |

**Поддомены бесплатны** — создаются в DNS-настройках регистратора домена. A-запись `db` → IP сервера. Платишь только за сам домен (~700 ₽/год), поддоменов сколько угодно.

---

## Защита от посторонних

Чтобы `db.romalex.ru` не находили случайные люди:

1. **Авторизация JWT** — без логина/пароля страница не открывается (уже реализовано)
2. **robots.txt** с `Disallow: /` — поисковики не индексируют
3. Ссылка нигде публично не публикуется — без прямой ссылки не найти

```
Интернет
    ↓

    ↓
┌─────────────────────────────────────┐
│  db.romalex.ru  →  FastAPI + SQLite │  ← таблица учёта
│  files.romalex.ru  →  Nextcloud     │  ← файлы фирмы
│  api.romalex.ru  →  FastAPI         │  ← OCR, аналитика
└─────────────────────────────────────┘
    ↓
Gemma 4 26B A4B MoE (локально, llama.cpp + Vulkan)
    ↓  Text-to-SQL + OCR
SQLite (данные складского учёта)
```

## Text-to-SQL аналитика

Работник пишет на русском → Gemma 4 26B A4B MoE переводит в SQL → результат в браузере.

Пример:
- «покажи расход труб за май» → `SELECT ... WHERE date >= '2026-05-01'`
- «что осталось на складе Киржач» → `SELECT ... WHERE location = 'Kirzach'`

Реализуется через Ollama + простая FastAPI обёртка.

## SSL / HTTPS

Let's Encrypt — бесплатно. Nginx + certbot, сертификат обновляется автоматически каждые 90 дней.

## Управление сервером

**Монитор** — нужен только при первоначальной настройке. После — всё через SSH с любого устройства.

**Claude Code на сервере** — ставится через npm:
```bash
npm install -g @anthropic-ai/claude-code
```
Заходишь по SSH → запускаешь `claude` → полноценный Claude Code в терминале. Настройка, написание кода, деплой сервисов — всё через него удалённо.

**Питание** — минимум сетевой фильтр Pilot (~500 ₽). Идеал — ИБП (~3-5к ₽): защита от скачков напряжения + время на корректное завершение при отключении света. Без ИБП при внезапном отключении SQLite может повредиться.

## Обоснование покупки сервера для директора

### Финансовая выгода

Аналог в облаке с такими же ресурсами (16 ядер, 64GB RAM, 16GB GPU, 4TB хранилище):

| Сервис | Цена/мес | За 2 года |
|---|---|---|
| Yandex Cloud (аналог) | ~25 000 ₽ | ~600 000 ₽ |
| Selectel (аналог) | ~18 000 ₽ | ~432 000 ₽ |
| **Домашний сервер** | ~300 ₽ (эл-во) | ~200 000 ₽ (покупка + эл-во) |

**Вывод:** за 2 года облако обходится в 2-3 раза дороже. Сервер окупается меньше чем за год.

Оформляется как покупка оборудования для фирмы — списывается с налогооблагаемой базы.

---

### Что конкретно получает фирма

**1. Складской учёт онлайн**
Таблица учёта материалов уже работает. Сейчас она локальная — с сервером любой мастер на объекте открывает `db.romalex.ru` с телефона и видит актуальные остатки в реальном времени. Прораб в Киржаче, директор в Москве — все смотрят одно и то же.

**2. Файловое хранилище**
Все рабочие документы, накладные, PDF-спецификации — в одном месте с доступом по ссылке. Не нужно пересылать файлы в WhatsApp и искать «ту самую версию» в переписке. Nextcloud — это корпоративный Dropbox, только данные хранятся у вас, а не у чужого облака.

**3. AI-аналитика по складу**
Прораб или директор задаёт вопрос на русском языке — «сколько медной трубы 22мм осталось на Киржаче?» — и получает ответ за секунды. Никаких Excel-фильтров, никого не надо дёргать. Локальная языковая модель, данные не уходят наружу.

**4. Автоматические бэкапы**
Каждую ночь база данных автоматически копируется на второй диск. Потеря данных исключена даже при сбое.

**5. IT-специалист в штате**
Сервер обслуживается, обновляется и развивается Арсением. Новые функции — по мере необходимости. Не нужно нанимать внешнего подрядчика или платить абонентку IT-компании.

## Удалённое управление сервером

[[ROMALEX]] |

**Стек удалённого доступа:**

- **Tailscale** — для себя. Ставится на сервак и на телефон/ноут, создаёт виртуальную сеть. Заходишь по SSH с любой точки мира как будто сервак рядом. Бесплатно, настройка 10 минут.
- **Cloudflare Tunnel** — для директора и монтажников. Таблица доступна по поддомену в браузере, без открытых портов.
- **Portainer** (опционально) — веб-морда для Docker. Управление контейнерами через браузер, без терминала. Для масштаба проекта не обязательно — хватит SSH.

**К серваку физически** нужно только один раз — установить ОС и настроить. Дальше всё удалённо: обновление БД, запуск скриптов, рестарт FastAPI — через SSH.

**Claude Code на сервере:**
Ставится через npm как обычный CLI. Авторизация через аккаунт — при первом запуске нужно залогиниться. Pro подписка работает на любом количестве устройств одновременно, привязана к аккаунту а не к машине.

## Структура двух SSD — финальное решение (19.06.2026)

[[ROMALEX]] | [[Таблица учёта по проектам]]

### Физическая разбивка дисков

```
Сервер (Minisforum UM890 Pro)
│
├── SSD 1 — Фирма (2TB)
│   ├── /db/          ← PostgreSQL (ROMALEX + будущие проекты)
│   ├── /cloud/       ← Nextcloud (~1.2TB, файловое облако фирмы)
│   └── /backups/     ← автокопия БД раз в сутки
│
└── SSD 2 — Личный
    ├── /glumo/       ← ГЛУМО FastAPI
    ├── /projects/    ← лендосы и прочее
    ├── /minecraft/   ← сервак
    └── /backups/     ← ночная копия SSD фирмы (если диск умрёт)
```

**Почему PostgreSQL а не SQLite:** роли (read-only для работников), Row Level Security, репликация в будущем. SQLite хорош для прототипа — PostgreSQL это фундамент на годы.

**Nextcloud:** корпоративный Dropbox на своём железе. Работники заходят, смотрят файлы, скачивают. Права на изменение — только у Арсения.

## Доступ работников — VPN решение (19.06.2026)

[[ROMALEX]] | [[Таблица учёта по проектам]]
	
**Требование:** без логина/пароля. Доступ только через VPN. У работников Android и iPhone.

### Итог исследования всех вариантов

| Вариант | Статус | Причина |
|---|---|---|
| Логин/пароль | ❌ | Неудобно, не масштабируется |
| Tailscale | ❌ | Геоблок РФ, App Store удаляет VPN-приложения |
| WireGuard чистый | ❌ | Блокируется ТСПУ с февраля 2026 |
| ANet (российский) | ❌ | Нет iOS клиента, молодой проект |
| **NetBird self-hosted** | ✅ **Финальный выбор** | Android + iOS, обходит ТСПУ через HTTPS 443, self-hosted |

### Почему NetBird

- Трафик через HTTPS порт 443 — ТСПУ не детектирует
- Приложения в Google Play и App Store
- Сервер управления на домашнем сервере — никакой зависимости от чужих облаков
- Уволить работника = кнопка в админке, мгновенно
- Бесплатно

### Известная проблема Android

Клиент нестабилен при переключении WiFi → мобильный (рейтинг 3.2★ Play Store). iOS и desktop — стабильны. Обязательно тестировать на реальных телефонах работников при настройке.

**План Б:** Headscale + официальный клиент Tailscale (стабильнее на Android).

### Как работает для работника

1. Скачал NetBird из Play Store / App Store
2. Перешёл по invite-ссылке от Арсения
3. Подключился — телефон в сети
4. Открыл браузер, `db.romalex.ru` — таблица без логина
5. Без NetBird — сайт вообще не существует в интернете
