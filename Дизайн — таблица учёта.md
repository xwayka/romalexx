# Дизайн — таблица учёта

[[ROMALEX]] | [[ROMALEX/Фронтенд — HTML CSS JS]]

---

## Аудитория

Система предназначена для **рабочих, монтажников и прорабов** — людей, которые хорошо знают своё дело, но не обязательно разбираются в интерфейсах. Пользователи будут работать с ней на планшете или ноутбуке прямо на объекте: в шуме, в рабочей одежде, с запыленными руками.

Из этого следует главный принцип: **простота и ясность важнее красоты**. Никаких иконок вместо слов. Никаких сокращений в заголовках. Шрифт крупнее чем хочется. Всё понятно с первого взгляда.

## Принципы дизайна

### 1. Зелёный акцент — корпоративный цвет Ромалекс

`#217346` — тот же зелёный что используется в Excel-таблицах компании. Это сознательное решение: система визуально связана с существующими документами компании. Hover на кнопках, выделение активной вкладки, аналитика «норма» — всё через этот цвет.

### 2. Прозрачные кнопки единого стиля

Все кнопки в интерфейсе — одинаковые: прозрачный фон (`var(--card)`), рамка (`var(--border)`), текст (`var(--text)`), hover зеленеет. Раньше кнопки в project-bar выглядели по-разному — это создавало ощущение что интерфейс «сделан из кусков». Унификация убрала этот визуальный шум.

### 3. Полные названия колонок без сокращений

В финальной версии: «Проектное кол-во», «Сметное кол-во», «Выполнение по КС», «Аналитика %». Вместо сокращённых «Пр», «См», «Вып». Монтажник не должен думать что означает «Пр» — приход или проектное. Ответ очевиден если написано полностью.

### 4. Крупный шрифт

Все размеры увеличены на +4px от первоначальных значений: тело документа 17px, шапка таблицы 16px, кнопки вкладок 18px. На планшете читается без напряжения.

### 5. Тёмная и светлая тема

Тёмная тема — основная для работы в помещении вечером или ночью. Светлая — для яркого уличного освещения на объекте. Переключатель в правом верхнем углу шапки.

## Анимация смены темы

Смена темы реализована через `clip-path: inset()` — **штора сверху вниз**. Overlay со старым цветом фона закрывает страницу, новая тема применяется под ним, затем overlay сдвигается вниз и исчезает.

Механика (JS, app.js → `toggleTheme()`):
1. Читается текущий `--bg` через `getComputedStyle`
2. В `<body>` добавляется `<div>` с `position:fixed; background: текущий --bg; clip-path: inset(0 0 0 0)`
3. Новая тема применяется сразу (`applyTheme(next)`) — она уже видна под overlay
4. После `getBoundingClientRect()` (force reflow) навешивается transition и `clip-path: inset(100% 0 0 0)` — верхний край уходит вниз за 0.42s
5. По `transitionend` overlay удаляется

Важно: CSS-transition на `body` убран (`transition: background 0.2s` удалён), иначе он конфликтовал с JS-анимацией и цвета мигали не в такт.

Выбор `inset()` вместо `circle()`: круговая анимация шла снизу-вверх (круг разворачивался вверх от кнопки), что выглядело как «всплытие». Сверху-вниз — интуитивно воспринимается как «смена экрана», похоже на переворот страницы.

## Структура страницы

```
┌─────────────────────────────────────────────────────┐
│ [Войти]     ROMALEX — Учёт материалов      [🌙/☀️]  │  ← header
├─────────────────────────────────────────────────────┤
│  ЖК Рязанский пр., вл.26/1 · ГСК 2/3  [Фото] [...]│  ← project-bar
├─────────────────────────────────────────────────────┤
│ [Труба] [Изоляция] [Автоматика] ... [СИЗ]          │  ← tabs
├─────────────────────────────────────────────────────┤
│  № │ Наименование │ Ед │ Пр.кол │ Киржач ПРО │ ... │  ← таблица
│    │              │    │        │ Пр│Рас│Ост │ ... │
├─────────────────────────────────────────────────────┤
│  данные...                                          │
└─────────────────────────────────────────────────────┘
```

**Header** — три зоны: авторизация (слева), логотип/название (центр), тема (справа). Фиксированный, прилипает при скролле.

**Project-bar** — одна строка с адресом объекта крупным шрифтом (22px) и кнопками действий. Кнопки видны всем, некоторые (загрузка фото) — только после входа.

**Tabs** — горизонтальный ряд из 8 вкладок. Активная вкладка выделена зелёным нижним бордером и цветом текста. Неактивные — серые.

**Таблица** — двухуровневая шапка (группы складов + подзаголовки), зафиксированная при горизонтальном скролле. Строки белые, hover — лёгкая зеленоватая подсветка.

## История дизайн-решений

### Почему убрали чередование цветов строк?

Первый прототип использовал zebra-striping (чередование серых и белых строк). От него отказались потому что при подсветке hover и при аналитическом выделении (перерасход/остаток) полосы создавали конфликт цветов. Чистый белый фон + hover дают более читаемую картину.

### Почему именно `#217346` а не другой зелёный?

Этот оттенок снят с корпоративных Excel-файлов Ромалекс — шапки их внутренних таблиц окрашены в этот цвет. Директор привык к нему визуально. Когда открываешь систему, она «ощущается» как документы компании — это снижает психологический барьер для новых пользователей.

### Почему прозрачный стиль кнопок, а не заливка?

Заливка (solid-кнопки) хорошо работает когда кнопка одна и является главным призывом к действию. В нашем интерфейсе несколько равнозначных кнопок (добавить, загрузить фото, статистика). Прозрачный стиль с рамкой делает их визуально одинаковыми по весу и не перетягивает внимание от таблицы.

## Цветовая аналитика

| Состояние | Цвет | Значение |
|---|---|---|
| Выполнение > Проектного | `#c0392b` (красный) | Перерасход — тревога |
| Выполнение = Проектному | нейтральный | Норма |
| Выполнение < Проектного | `#217346` (зелёный) | Остаток — всё хорошо |

## UI-правки сессии 06.06.2026

### Кнопка темы — фиксированная ширина

Кнопка переключателя темы прыгала по ширине при смене текста «Светлая тема» ↔ «Тёмная тема» (разная длина). Решение: `min-width: 170px; justify-content: center` — кнопка всегда одного размера. Текст метки обновляется в `applyTheme()`.

### Карточка проекта — прозрачный стиль

Карточка проекта на главном экране унифицирована с прозрачными кнопками хедера:
- Тёмная тема: `background: rgba(255,255,255,0.10)`, `border: 1.5px solid rgba(255,255,255,0.25)`
- Светлая тема: `background: rgba(0,0,0,0.04)`, `border: 1.5px solid rgba(0,0,0,0.12)`
- `border-left: 4px solid var(--accent)` — корпоративный зелёный акцент сохранён

### Модалка подтверждения скачивания Excel

Полный редизайн `#modal-download`:
- Убрана иконка ✓ с зелёным фоном
- Порядок: «Проект: ЖК Рязанский пр., вл.26/1 · ГСК 2/3» → «Актуально на: дата&nbsp;время»
- `&nbsp;` между датой и временем — не переносятся на разные строки
- Шрифты: 20px / 19px (минимальная разница чтобы был акцент)
- `max-width: 500px` — блок шире прежнего
- Кнопка × → таймер 2→1→×: пока `disabled` выглядит как белая пилюля с числом, после 2 секунд становится обычным ×
- Клик мимо модалки заблокирован пока кнопка `disabled`

### Хедер — увеличен масштаб

Header вырос: `min-height: 52px → 66px`, `padding: 10px → 14px`. Все шрифты +2px: логотип `23px → 25px`, кнопки `17px → 19px`, SVG-иконки `16px → 18px`. Причина — на планшете в реальных условиях объекта должно быть крупнее и удобнее для нажатия пальцем.
