# LLM интеграция — ROMALEX таблица учёта

[[ROMALEX]] | [[Архитектура сервера]]

> Цель: Gemma 4 26B A4B MoE через llama.cpp + Vulkan живёт на сервере (UM890 Pro) и знает всю базу данных. Упрощает ежедневную работу — аналитика, поиск, авто-матчинг накладных, сводки.

---

## Фаза 1 — Аналитический чат (приоритет)

Чат-панель прямо в интерфейсе таблицы. Пользователь пишет вопрос на русском — получает ответ.

**Архитектура:**
```
Вопрос на русском
      ↓
POST /api/analytics { "question": "...", "tab": "raskhodnik" }
      ↓
Шаг 1: Gemma генерирует SQL (промпт содержит схему БД + вопрос)
Шаг 2: бэкенд выполняет SELECT (только чтение, иначе 403)
Шаг 3: Gemma форматирует результат в человеческий текст
      ↓
Ответ пользователю
```

**Примеры запросов:**
- «сколько хомутов 3/4 осталось на Киржаче?»
- «покажи расход за май»
- «что было в последней накладной от СЭМПРО?»
- «какие позиции в минусе?»
- «топ 5 самых расходуемых материалов»

**Безопасность:** бэкенд парсит сгенерированный SQL и разрешает только SELECT. Любой INSERT/UPDATE/DELETE — 403.

---

## Фаза 2 — Умный авто-матчинг OCR

Сейчас: накладная распознана → пользователь вручную сопоставляет каждую строку с позицией в БД.

С LLM: при OCR бэкенд передаёт Gemma список всех позиций из БД + распознанные строки накладной. Модель сама предлагает совпадения по смыслу.

«Хомут оц. стандартный с рез. прок. 3/4» → `Хомут для крепления труб оцинкованный стандартный с резиновой прокладкой 3/4"`

Пользователь только подтверждает или исправляет — вместо ручного выбора из 200+ позиций.

---

## Фаза 3 — Ежедневные сводки

Кнопка «Сводка за сегодня / за неделю» → Gemma анализирует операции за период и выдаёт читаемый текст:

- Что пришло, откуда, в каком количестве
- Что ушло и куда
- Что критически мало (остаток < 10% от проектного)
- Аномалии (расход больше прихода за период)

## Итоговое состояние (обновлено 23.06.2026)

**Модель:** `gemma4:26b A4B MoE` (17 GB, MoE — активных параметров всего 4B → скорость как у маленькой модели) — на домашнем сервере **Minisforum UM890 Pro** (Radeon 780M iGPU, 32GB RAM unified → апгрейд до 64GB в августе).

**Почему MoE, а не Dense:** MoE активирует только 4B параметров из 26B → скорость как у 4B-модели, качество как у 26B. При 32GB RAM влезает без оффлода.

**Почему llama.cpp + Vulkan, а не Ollama:** Ollama на Radeon 780M = **4.5 tok/s**. llama.cpp + Vulkan бэкенд = **22–25 tok/s**. Разница 5–6× только от способа запуска. Настраивать через `llama-server --n-gpu-layers 99 -b vulkan`.

**Ключевые параметры `/api/chat`:**
- `think: false` — отключает режим мышления (иначе модель думает, content пустой)
- `num_ctx: 16384` — данные склада (114 позиций) = ~8500 токенов на русском. Дефолт 4096 обрезал промпт.
- `timeout: 300s` — запас на медленную генерацию

**Состав system-промпта:**
1. Инструкция аналитика (роль, ограничения)
2. Текущая дата (`datetime.date.today()`)
3. Последние 50 операций с датами — чтобы иишка понимала «вчера», «сегодня»
4. Суммарные остатки по всем 114 позициям

**История чатов:** `num_ctx: 32768`, история из `chat_messages` передаётся в `messages[]` после system. Каждый пользователь видит только свои чаты (по JWT username).
