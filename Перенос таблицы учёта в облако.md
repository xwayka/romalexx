# Перенос таблицы учёта в облачное хранилище ROMALEX

[[ROMALEX]] | [[ROMALEX/Облачное хранилище ROMALEX — концепт|Концепт облака]] | [[ROMALEX/Таблица учёта по проектам|Таблица учёта]]

## Суть решения

Таблица учёта материалов (сейчас работает как FastAPI + SQLite webapp) переезжает в облачное хранилище ROMALEX на домашнем сервере **Minisforum UM790 Pro**.

Таблица будет жить как **`.xlsx` файл** в разделе Документов облачного хранилища. Редактировать её можно прямо в браузере через **OnlyOffice Community Edition** — это как Google Таблицы, только своё, на своём сервере, бесплатно.

## Почему .xlsx, а не SQL база

Сейчас все работники и кладовщики ведут учёт в Excel — это привычный инструмент. SQL-база это отдельный слой, который требует:
- разработку и поддержку бэкенда
- обновление через специальный веб-интерфейс
- постоянную синхронизацию с реальным Excel у сотрудников

Когда сервер будет настроен — xlsx-файл просто перекладывается в облако. Работники открывают браузер, видят знакомую таблицу, редактируют прямо там. Никакой дополнительной разработки.

> В будущем таблицу **возможно** перенесут в полноценную БД — но это не точно и не сейчас.

## Доступ к серверу

Вход в облачное хранилище только через **Tailscale** или **NetBird** — это закрытая сеть только для своих, в открытый интернет сервер не торчит. Директор, кладовщик, бухгалтерия — каждый со своим логином.

## Стек на сервере

- **Nextcloud** — само облачное хранилище (файлы, папки, роли)
- **OnlyOffice Community Edition** — редактор xlsx/docx прямо в браузере
- **Docker** — каждый сервис изолирован в своём контейнере
- **Tailscale / NetBird** — защищённый доступ

## Фазы реализации

1. **Фаза 1 — UI** (текущая): довести `cloud-ui-concepts.html` до идеала, без бэкенда
2. **Фаза 2 — Рабочий продукт**: авторизация, файлы, роли, графы — полная функциональность без реальных данных
3. **Фаза 3 — Перенос таблицы**: сервер приехал (начало июля), поднять Nextcloud + OnlyOffice, закинуть `.xlsx`, подключить редактор
