## 2. ФАЙЛОВАЯ СИСТЕМА — РАЗДЕЛЫ

### Документы (общий раздел, доступен всем)
- Один в один как проводник Windows
- Сортировка по имени, дате, типу
- Переключение видов (список / плитка)
- ЛКМ = открыть, ПКМ = контекстное меню (переименовать, скачать, сделать публичным)
- **Без цветных иконок** — монохром с обводкой
- Tooltip при наведении: тип файла (папка / таблица / PDF / текст / фото)
- Объём: **~600 GB на общем диске** (выделен на сервере)

### Личное (у каждого сотрудника)
- **Лимит: 10 GB на человека**
- Те же файловые операции, что в Документах
- Файлы можно сделать публичными → запрос на одобрение к Admin
- Только после одобрения Admin/Директора файл появляется в общем доступе
- При удалении публичного файла → диалог: "Перенести в общий диск?"

### Заметки
- MD-файлы, редактор прямо в интерфейсе
- Галочки, списки, базовое форматирование Markdown
- Доступны каждому, личные (не общие по умолчанию)

### Проекты
- Папки привязанные к конкретным объектам (GSK, Coffee Mania, Balance и т.д.)
- Нажатие = открывается отфильтрованный проводник только по этому проекту

### Недавние
- Файлы добавленные/изменённые за последние **3 дня**
- Выпадает снизу при нажатии на пункт меню (как в Windows Explorer)

### Теги
- **Только для графа связей**
- Теги хранятся в БД на уровне каждого файла
- **Глобальные теги** (для общих файлов) — только Арсений назначает
- **Личные теги** (для своих файлов) — каждый сам

## 4. ДАШБОРД (реализация — потом)

### Концепция: виджетный дашборд
- По умолчанию: пустые блоки-плейсхолдеры с подписью "Настройте под себя"
- У каждого блока ⚙️ (шестерёнка) → меню выбора виджета
- Виджеты: диаграммы, столбики, календарь, таблицы, недавние заметки, слайдеры

### Кастомизация:
- Пользователь выбирает **какие виджеты** показывать
- Пользователь **регулирует размеры** (drag-to-resize)
- Цвет менять нельзя — только яркость/контрастность синего (один параметр)
- Поиск по файлам — **не на дашборде** по умолчанию (это отдельный виджет)

### AI-ассистент в сайдбаре:
- Мини-чат с Gemma встроен в сайдбар
- Называется "Консультант" (можно переименовать)
- Анализирует файлы, отвечает на рабочие вопросы

## 5. ПРАВА ДОСТУПА (RBAC)

### Роли:
| Роль | Доступ |
|---|---|
| **Admin (Арсений)** | Полный доступ, одобрение публикаций, Admin-панель, **единственный кто обновляет общие файлы** |
| **Директор (папа и др.)** | Видит личные файлы сотрудников, блокирует доступы, Admin-панель |
| **Сотрудник** | Документы (только чтение, по разрешению), Личное (10GB), Заметки, Проекты (чтение), запрос публикации |

### Правила доступа к общим файлам:
- **Общие файлы** — сотрудники имеют доступ **только по разрешению** и **только на чтение**
- **Обновить/заменить общий файл** — только Admin
- **Одинаковое имя файла** — НЕ заменяется автоматически, диалог: "Файл с таким именем существует. Переименовать или отменить?" Только Admin может принудительно заменить
- Сотрудник никогда не может загрузить что-то прямо в общий раздел — только через workflow публикации с одобрением Admin

### Выдача логинов:
- **Арсений выдаёт логин + роль** каждому вручную — никакой саморегистрации
- Причина: исключить фейки и случайное повышение прав
- Тестовый период: **3-4 месяца**, доступ не у всех сразу

### Admin-панель:
- Кто что загружал (лог активности)
- Одобрение/отклонение заявок на публикацию файлов
- Управление ролями пользователей
- Мониторинг использования хранилища

### Личное хранилище — защита от злоупотреблений:
- Только рабочие файлы, не семейные фото
- Admin видит всё что загружается (логирование)
- Возможно: блокировка типов файлов (фото/видео без рабочего контекста)

## 6. WORKFLOW ПУБЛИКАЦИИ ФАЙЛОВ

```
Сотрудник создаёт файл
        ↓
Хранится в Личном (10GB)
        ↓
ПКМ → "Сделать публичным" → заявка Admin
        ↓
Admin/Директор просматривает файл
        ↓
    ДА                    НЕТ
     ↓                     ↓
Дублируется            Остаётся
в Документы            в Личном
(общий диск)
```

### При удалении публичного файла:
```
Сотрудник жмёт "Удалить"
        ↓
Диалог: "Файл в общем доступе.
         Перенести на общий диск или удалить везде?"
        ↓
Заявка → Admin одобряет/отклоняет
        ↓
    ПЕРЕНЕСТИ              УДАЛИТЬ
         ↓                     ↓
Файл остаётся в        Удаляется везде,
общем диске,           память освобождается
память освобождается
у сотрудника
```

## 7. ЖЕЛЕЗО И МАСШТАБИРУЕМОСТЬ

### Конфигурация сервера:
- **Minisforum UM890 Pro** (AMD Ryzen 9 8945HS, Radeon 780M iGPU)
- **32 GB RAM**
- **1 TB** — под OS + личные файлы Арсения
- **2 TB** — под общие файлы + таблицы учёта

### Моя оценка мощности для задачи:
- **20-50 одновременных пользователей** — Ryzen 9 7940HS справится. При 50+ узкое место — **SSD I/O** (одновременные upload/download), не CPU/RAM. Решение: очередь загрузки + rate limiting.
- **Gemma 4 26B MoE (4-bit)** — ~~13 GB~~ **реально 18-24 GB RAM** (по данным от Gemini: AWQ/GGUF 4-bit на 26B модели). UM790 Pro с 32 GB RAM НЕ потянет: 20 GB на модель + 8 GB OS = 4 GB на FastAPI, это критически мало.
- **Рекомендация по AI**: использовать **Gemma 9B** (4-bit ≈ 5-6 GB RAM) — нормально влезает. Или вынести AI на cloud API (Claude/Gemini), не гонять локально. Gemma 26B — только если апгрейд RAM до 64 GB.
- **Узкое место при 50+ пользователях** — SSD I/O при массовых загрузках. Решение на том этапе: upload queue + bandwidth throttling.

### Storage-план:
```
2 TB диск:
├── ~600 GB — общий диск Документы/Проекты
├── ~N*10 GB — личные хранилища сотрудников
├── ~200 GB — резерв для таблиц учёта (если мигрируем из Excel)
└── ~остаток — логи, бэкапы
```

## 8. ТАБЛИЦЫ УЧЁТА — РЕШЕНИЕ

### Решение: оставить как .xlsx, НЕ мигрировать в SQL

**Обоснование Арсения:** все сотрудники работают в Excel, нет смысла дублировать данные из Excel в SQL — двойной вес и рассинхронизация.

**Это правильно в данном контексте:**
- Таблица учёта хранится на облачном сервере как .xlsx файл
- Редактируют её только 2-3 человека с правами (Admin/Директор)
- Остальные — только чтение по разрешению
- Одновременных редакторов ≤ 3 человек

### Почему конфликтов нет:
File lock не нужен — права доступа решают проблему автоматически. Только Admin обновляет общий файл. Если закупщик хочет внести данные — он загружает к себе в Личное, правит, отправляет запрос. Admin принимает решение и сам обновляет общий файл.

### Про OCR:
OCR (распознавание накладных) — только для AI-ассистента, не для автозаписи в таблицу. Не нужно.

### MVP-workflow для таблицы учёта:
```
Скачать .xlsx → открыть в Excel → отредактировать
→ загрузить обратно (только Admin)
→ старый файл заменяется только вручную Admin'ом
```

## 9. СОВМЕСТИМОСТЬ ФАЙЛОВ (Word/LibreOffice)

### Требование Арсения: один в один при загрузке/выгрузке

**Честная оценка:** это самая сложная часть проекта. "Один в один" — практически невозможно для всех форматов из-за различий в рендерере Word и LibreOffice. Но есть решения:

| Подход | Плюсы | Минусы |
|---|---|---|
| **OnlyOffice** (self-hosted) | Максимальная совместимость с .docx/.xlsx, открытый исходник | Требует 2-4 GB RAM |
| **LibreOffice Online** (Collabora) | Бесплатно, хорошая совместимость | Тяжелее в настройке |
| **Внешний редактор** (открываем файл в Windows) | Ноль проблем с совместимостью | Нет редактирования прямо в браузере |

**Рекомендация:** на этапе MVP — открывать файлы в локальном приложении (Word/LibreOffice), без встроенного редактора. Это реалистично для первых 3-4 месяцев теста. OnlyOffice подключить позже, когда базовая система стабилизируется.

## 11. ХОРОШИЕ ИДЕИ (оцениваю как директор, не как подпевала)

✅ **Виджетный дашборд** — отличная идея, люди разные, одни хотят календарь, другие таблицы. Grid-based layout с drag-resize — реализуемо через CSS Grid + Interact.js.

✅ **Граф как в Obsidian** — умно. Рабочие не оценят сложный кастом, а знакомая концепция из популярного инструмента снизит порог входа.

✅ **Одобрение публикаций** — правильное решение для корпоративной системы. Без этого через неделю в "общем доступе" будут мемы и личные фото.

✅ **Логин выдаётся вручную** — абсолютно верно для первого теста. Self-регистрация — дыра в безопасности.

✅ **Лимит 10 GB на личное** — справедливо для рабочего хранилища. Если кто-то хочет больше — это флаг для проверки.

⚠️ **Кастомизация цвета (яркость синего)** — технически несложно (CSS-переменные + range input), но смысл сомнительный. Лучше потратить это время на стабильность функционала. Оставь на потом.

⚠️ **AI-ассистент в сайдбаре** — хорошо для будущего, но Gemma 26B займёт 18-24 GB RAM — не влезает в 32 GB. Использовать Gemma 9B (5-6 GB) или cloud API. Реализовывай в последнюю очередь.

❌ **"Один в один Word/LibreOffice"** — нереалистично без OnlyOffice. Не обещай это пользователям на старте. MVP: "открывается в вашем редакторе".
